1. Uniforms and the Animation Loop

In the previous demo, all data came from a buffer: every vertex had its own position and color. A uniform is different. It has one value for the whole draw call, and every vertex and every pixel sees the same value. Uniforms are how JavaScript talks to the shaders: the elapsed time, a color from a color picker, a number from a slider.

3. How It Works

The source of this page uses the same six steps as the Triangle demo. Only what is new is marked in the code with NEW in this demo:

  1. Get the context. Same as before.
  2. Write the shaders. New: four uniform declarations. The vertex shader scales the quad with u_time and u_pulse; the fragment shader draws the glow.
  3. Compile and link. New: getUniformLocation looks up where each uniform lives. This happens once, not every frame.
  4. Upload the vertex data. A quad with four vertices (position and texture coordinate each).
  5. Describe the layout and record a VAO. Same idea as before, with a_uv instead of a color.
  6. Animate. New: a requestAnimationFrame loop. Every frame it advances the time, sets the uniforms and draws.

Why is time accumulated? The loop adds a small step to time every frame (the time since the last frame, multiplied by the speed). If it used the raw timestamp multiplied by the speed instead, then changing the speed after one minute would make the animation jump to another point in time. Pausing works the same way: no step is added.

Why is x divided by the aspect ratio? This canvas is wider than it is tall, but clip space still runs from −1 to +1 on both axes. The shader divides x by u_aspect (width divided by height), so the circle stays a circle when the canvas is resized. This fixes the stretching of the first demo.

Why is the step limited? The browser stops calling requestAnimationFrame while the tab is hidden. When you come back, one frame would see a huge time step. The code caps the step at 100 ms.
