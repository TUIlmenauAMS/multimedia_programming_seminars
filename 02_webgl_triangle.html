1. Your First WebGL 2 Program

This demo draws a single triangle. Even this smallest possible scene needs the whole WebGL structure: a context, two shaders, a buffer with vertex data, a Vertex Array Object and a draw call. Everything later in this chapter builds on it.

Each of the three vertices carries a position and a color. The vertex shader passes the color on as a varying. During rasterization the GPU interpolates it across the triangle, and the fragment shader runs once for every pixel inside it.

Vertex data → Vertex shader → Rasterization → Fragment shader → Canvas

3. How It Works

The source of this page is organized in numbered steps. Open it in your editor next to the running demo:

  1. Get the context. canvas.getContext('webgl2') returns null if WebGL 2 is not available, so the result is always checked.
  2. Write the shaders. A vertex shader and a fragment shader in GLSL ES 3.00, stored as JavaScript strings.
  3. Compile and link. The driver compiles the strings at runtime. Compile and link errors are printed and shown in the page.
  4. Upload the vertex data. One interleaved Float32Array (x, y, r, g, b per vertex) is copied into a GPU buffer.
  5. Describe the layout and record a VAO. Stride and offset tell WebGL how to read the buffer; the Vertex Array Object remembers the setup.
  6. Draw. Set the viewport, clear, select the program and the VAO, and call drawArrays.

Why is there no animation loop? The scene never changes by itself, so it is drawn once and again only when something changes: a resize or a toggle. Steps 1 to 5 run once at start-up. Only step 6 is repeated.

Why is the canvas square? Clip space always runs from −1 to +1 on both axes, whatever the shape of the canvas. On a wide canvas the triangle would be stretched. The next demo fixes this with an aspect-ratio uniform.
