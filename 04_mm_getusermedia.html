getUserMedia — Media Capture & Constraints

This demo is purely about capturing media from the user's devices — before any peer connection or signaling is involved. You will see how the browser requests permission, how constraints shape what is captured, and how to inspect what the browser actually granted via MediaStreamTrack.getSettings().

Teaching focus: permission model · constraints vs settings · MediaStreamTrack properties · device enumeration · soft mute vs hardware stop.

See Section 8 of the theory HTML for the full explanation of the getUserMedia API.

Device Enumeration — enumerateDevices()
// CONCEPT: Privacy & device labels
enumerateDevices() always returns a list of devices, but device.label is an empty string until the user grants camera/mic permission. This is a deliberate fingerprinting protection — a page cannot silently discover your hardware before you consent.

Switching stops the current tracks and calls getUserMedia() again with deviceId: { exact: … }. The old tracks must be stopped first to release the hardware.
