1. Into the Third Dimension: the MVP Pipeline

Moving from 2D to 3D requires three matrices chained together — the MVP pipeline. The Model matrix places the object in the world (rotation, translation, scale). The View matrix moves the world in front of a fixed camera. The Projection matrix maps the 3D scene onto the 2D canvas, adding perspective foreshortening so distant objects appear smaller.

In the vertex shader: gl_Position = u_projection × u_view × u_model × vertex. The rightmost matrix is applied first, as always. The result is a 4-component clip-space coordinate; the GPU divides by w (the perspective divide) and then maps the result to the viewport.

Depth test. WebGL keeps a depth buffer — one depth value per pixel. Before writing a pixel, the GPU checks whether it is closer than what was already there. If not, it is discarded. This ensures the front face always wins, regardless of draw order.

Face culling. Every triangle has a front side and a back side, determined by the winding order of its vertices. With culling on, the GPU skips back-facing triangles entirely — roughly halving the fragment work. The cube's triangles are wound counter-clockwise when seen from outside, so back faces (pointing away from the camera) are culled.

Index buffer. Instead of repeating vertex data for shared edges, we store 24 unique vertices (4 per face) and a separate list of 36 indices (6 per face × 6 faces = 36) that reference them. The GPU reads the indices and fetches the right vertex for each triangle.

3. How It Works

The source follows the same numbered steps as earlier demos. The new pieces introduced here:

  1. mat4 helpers. All transforms are now 4×4 column-major matrices. The perspective matrix encodes the field of view and near/far clip planes.
  2. Cube geometry. Built from a table of 6 faces. Each face contributes 4 vertices (with the face color) and 6 indices (two triangles, wound CCW from outside). The index buffer sits in the VAO so drawElements can reference it.
  3. Three uniform matrices. u_model, u_view and u_projection are uploaded separately each frame. The view matrix places the camera at distance d on the +z axis looking at the origin: view = translation(0, 0, -d).
  4. Depth and cull state. gl.enable/disable(gl.DEPTH_TEST) and gl.enable/disable(gl.CULL_FACE) are set every frame to keep the toggles responsive.
  5. Pointer drag. pointerdown / pointermove / pointerup with setPointerCapture work for mouse and touch alike.

Why turn off depth test? When the depth test is off, every fragment overwrites the pixel regardless of depth. For a cube this means the last face drawn always "wins" — you see faces painted on top of nearer ones. The draw order in the index buffer determines what is visible, which is arbitrary and looks wrong.

Why turn off culling? Without culling, back-facing triangles are drawn too. With the depth test on, this still looks correct (the front face wins). With both off, you get the full chaos.
