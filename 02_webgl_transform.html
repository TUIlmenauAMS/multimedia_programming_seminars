1. Matrices as Composable Transformations

A transformation matrix encodes translation, rotation or scale as a single mathematical object. To move a 2D point with a matrix, we extend it to homogeneous coordinates — a 3-component vector (x, y, 1) — and multiply: p′ = M · p. The matrix lives in the vertex shader, so the GPU applies it to every vertex in parallel without touching the CPU after the upload.

The real power is composition: multiplying two matrices together gives a single matrix that does both transforms in one step. But matrix multiplication is not commutative — order matters. Translating first and then rotating gives a completely different result from rotating first and then translating.

Column-major storage. GLSL and WebGL store matrices column by column in memory, not row by row. A mat3 passed with uniformMatrix3fv must therefore be laid out as column 0 first, then column 1, then column 2. The matrix readout below shows the matrix in the usual mathematical (row-major display) notation, so the numbers you see match what you would write on paper — but the array in memory is transposed relative to that.

Read the formula right to left. When we write M = T · R · S, the rightmost factor (S) is applied first. This is because we compute M · p = T · (R · (S · p)): S acts on the point first, then R, then T.

3. How It Works

The source is split into numbered steps. Open it in your editor alongside the running demo:

  1. Get the context. Same as Demo 1 — getContext('webgl2'), check for null, show an error banner if unavailable.
  2. Write the shaders. The vertex shader has one new line compared to Demo 1: gl_Position = vec4(u_matrix * vec3(a_position, 1.0), 0.0, 1.0). The whole transformation lives in one uniform matrix upload.
  3. Compile and link. Same helpers as Demo 1.
  4. Upload geometry. Two separate VAOs: the letter "F" and the reference grid. Both use the same program; the grid is drawn with the identity matrix and a gray color.
  5. Wire the UI. Each slider updates a state variable. The matrix is re-composed from those values on every frame.
  6. Render loop. requestAnimationFrame accumulates time for the auto-rotate animation. The matrix is built, uploaded as a uniform, and the draw call is made.

Why a letter "F"? Any symmetric shape (circle, square) looks the same after rotation, so you cannot tell rotation from the identity at a glance. The F has a clear top, a horizontal bar, and a stub — making every transformation immediately visible.

Why column-major? OpenGL (and WebGL) historically stores matrices column by column in memory. The mat3 helper in this demo therefore stores columns, and uniformMatrix3fv(loc, false, m) — note false, meaning "do not transpose" — passes the array straight to the GPU. The live readout above re-indexes into row-major display so the numbers match the textbook.
