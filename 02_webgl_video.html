1. Video as a Texture

A video is just a texture whose pixels change every frame. Instead of uploading an image once, the render loop calls gl.texImage2D every frame with the current video frame as the source. Everything else — UV coordinates, filtering, the sampler uniform — works exactly as in Demo 5.

Once the video frame lives in GPU memory as a texture, the fragment shader runs once per pixel in parallel. A 1080p frame has about 2 million pixels, and the GPU processes them all at the same time. This makes image-processing filters — grayscale, edge detection, blur — trivially fast: the vertex shader just draws a fullscreen quad; the fragment shader does all the work.

Per-frame upload: each frame, if the video is ready (readyState ≥ HAVE_CURRENT_DATA), the demo calls gl.texImage2D(..., videoElement) to replace the texture contents. No mipmaps are generated (it would require regenerating them for every frame — use LINEAR min-filter instead). CLAMP_TO_EDGE is set so the video edges don't bleed.

Optimisation note: texSubImage2D can update a sub-region without reallocating; requestVideoFrameCallback fires only when a new frame is decoded, avoiding redundant uploads. Both are mentioned in code comments but not implemented here for clarity.

3. How It Works

This demo is Demo 5 with the cube replaced by a fullscreen quad and the static texture replaced by a live video feed. The key differences:

  1. Three frame sources. getFrameSource() returns either a <video> element or a procedurally animated 2D <canvas> — the render loop does not need to know which.
  2. Per-frame texture upload. Each frame, if the source has data, texImage2D is called with the source element. The texture is set up once at init with LINEAR filtering and CLAMP_TO_EDGE wrapping, and mipmaps are skipped.
  3. Letterboxing. The vertex shader receives a u_scale vec2 that shrinks the quad so the video's aspect ratio is preserved within the canvas. The area outside stays the canvas background color.
  4. Split view. A second varying, v_canvasUv, carries the canvas-relative x position (0…1). The fragment shader uses it — not v_uv — to draw the divider line and select left (original) vs right (filtered).
  5. Seven filters implemented as GLSL functions, selected at runtime by uniform int u_filter. Each function takes and returns a vec3 color. Neighbor sampling (Sobel, blur) uses textureSize(u_texture, 0) to compute a texel step.

Webcam and file://: getUserMedia requires a secure context (HTTPS or localhost). When run via file://, the browser may block it. The demo catches the failure, shows an error banner, and falls back to the animated pattern. Switching sources stops old media tracks and revokes any object URL to avoid leaks.

GPU cost model: if/else if on a uniform in GLSL ES 3.00 is legal and clear for teaching. On a GPU, branches that are uniform (all threads take the same path) are cheap — the driver compiles them as conditional moves or separate code paths. Dynamic branches on per-pixel data would cost more.
