1. Why PySide6 for Multimedia Applications

In Chapter 01 you built audio tools in the browser using the Web Audio API, and in Chapter 02 you rendered graphics in the browser using WebGL 2. The browser is a powerful platform for educational tools and lightweight interactive applications. But it has hard limits that rule it out for professional multimedia software:

  • Latency: the browser audio stack has latency measured in tens of milliseconds. Professional audio tools require latency under 10 ms, often under 5 ms. PortAudio — the library behind sounddevice — can achieve 1–3 ms round-trip latency on a properly configured system.
  • File system access: browsers cannot open arbitrary files or write to disk. Professional tools work with large media files that may be gigabytes in size.
  • OS audio APIs: professional applications need direct access to ASIO (Windows), ALSA (Linux), and CoreAudio (macOS) drivers. The browser exposes none of these.
  • Hardware integration: MIDI controllers, audio interfaces, video capture cards, and broadcast hardware are not accessible from a browser.
  • Processing power: real-time DSP on long audio files, multi-channel processing, and high-resolution video all require the full CPU without JavaScript's single-threaded constraint.

This is the gap that Python + Qt fills. Qt is a C++ framework used as the UI layer in Avid Pro Tools, Adobe Audition, DaVinci Resolve, VLC, and many other professional multimedia applications. PySide6 gives you Python bindings to the same framework under an LGPL licence — meaning you can use it in commercial products without paying a licence fee.

PySide6 vs PyQt6

PySide6 and PyQt6 expose identical APIs — they are both Python bindings to the same Qt 6 C++ library. The difference is licensing. PyQt6 is released under the GPL, which means any software you distribute using it must also be open source under the GPL. PySide6 is released under the LGPL, which means you can link it into a closed-source commercial application without releasing your source code. Studios and broadcast companies use PySide6. Use PySide6 for any project that might be commercialised.

The tools you learn here are production tools. sounddevice wraps PortAudio, the cross-platform audio I/O library that underpins Audacity, PortMidi, and dozens of DAW plugins. soundfile wraps libsndfile, used in virtually every professional audio application on Linux. OpenCV is used by every major film studio's VFX pipeline and by every major technology company's computer vision team. You are not learning toy libraries — you are learning the stack that professionals use.

3. PySide6 Architecture for Multimedia

Every PySide6 application shares the same fundamental structure: a QApplication that owns the event loop, a hierarchy of widgets that make up the UI, a layout system that manages their geometry, and a signals-and-slots mechanism that wires them together. This section covers these concepts in the context of multimedia applications.

QApplication and the event loop

QApplication must be created before any widget and exactly once per process. It initialises Qt's platform plugin (the bridge to the OS window manager), processes command-line arguments, and owns the event loop. app.exec() starts the event loop, which blocks until the last window is closed. The exit code it returns should always be forwarded to the OS:

import sys
from PySide6.QtWidgets import QApplication

app = QApplication(sys.argv)  # must come before any QWidget
window = MainWindow()
window.show()
sys.exit(app.exec())           # app.exec() returns 0 on clean exit

The event loop is the same concept as the browser's event loop that drove requestAnimationFrame in Chapter 01 and Chapter 02. It waits for events — user input, timer expiry, repaint requests — and dispatches them to the correct handlers. Your code does not run continuously; it runs in response to events.

Signals and slots in a multimedia context

The signals-and-slots mechanism is Qt's implementation of the observer pattern. An object emits a signal when something happens; any number of other objects can connect slots (callback functions) to that signal and be notified automatically. The emitter does not know who is listening.

In a multimedia application this decoupling is essential. A frequency slider does not know that an audio engine exists. It emits valueChanged(int). The audio engine is a slot that receives the value and updates its DSP parameter. If you later replace the audio engine, the slider needs no changes:

from PySide6.QtCore import Signal, QObject

class AudioEngine(QObject):
    # Custom signal — emitted when the playhead moves (from the audio thread
    # via a queue, dispatched to Qt in the main thread)
    frame_changed = Signal(int)

# Connect the slider to the engine's parameter setter
freq_slider.valueChanged.connect(audio_engine.set_frequency)

# Connect the engine's signal to the waveform display
audio_engine.frame_changed.connect(waveform_view.set_playhead)

You can also define custom signals that carry data across threads. The key rule: always emit signals in the Qt main thread. Data produced in the audio thread must be placed in a queue.Queue and consumed by the main thread via a QTimer.

In a professional multimedia tool, the UI never calls DSP functions directly. A slider emits a signal carrying its value; the DSP component is a slot that receives it. This decoupling means you can replace the UI or the DSP engine independently, test each component in isolation, and connect them together in any combination. It is the same architectural principle that makes Maya's node graph and Houdini's operator network so powerful.

4. Audio I/O with sounddevice

PortAudio is the cross-platform audio I/O library that powers Audacity, dozens of DAW plugins, and professional broadcast tools. sounddevice is the authoritative Python interface to PortAudio. It gives you direct access to your system's audio hardware with latencies that the browser can never achieve.

Device enumeration

Before opening an audio stream, list the available devices and select the right one. In a professional application, the selected device is stored in user preferences and restored at startup:

import sounddevice as sd

# List all audio devices on the system
print(sd.query_devices())

# Get the default input and output devices
default_in  = sd.query_devices(kind='input')
default_out = sd.query_devices(kind='output')

print(f"Default input:  {default_in['name']}  @ {default_in['default_samplerate']} Hz")
print(f"Default output: {default_out['name']} @ {default_out['default_samplerate']} Hz")

ModeAPIWhen to use
Blockingsd.play(), sd.rec(), sd.wait()Simple one-shot playback or recording from a script. Not suitable for interactive applications.

The audio callback — the professional pattern

In callback mode, you provide a function that PortAudio calls from its own high-priority audio thread at exactly the right time to fill or drain a hardware buffer. This is the pattern used in every real-time audio application:

import sounddevice as sd
import numpy as np

SAMPLE_RATE = 48000   # Hz — standard for professional audio
BLOCK_SIZE  = 512     # frames per callback block — lower = less latency, higher CPU

def audio_callback(outdata: np.ndarray,
                   frames: int,
                   time_info,
                   status: sd.CallbackFlags) -> None:
    """Called by PortAudio every BLOCK_SIZE / SAMPLE_RATE seconds.

    CRITICAL RULES for this function:
    1. Never allocate memory (no list(), no np.zeros(), no new objects).
    2. Never call Qt functions — this is not the main thread.
    3. Never perform blocking I/O (no file reads, no network calls).
    4. Never hold a lock for more than a few microseconds.
    5. Always fill outdata completely — leaving it uninitialised causes noise.
    """
    if status.output_underflow:
        # Underflow means Qt or the OS blocked the audio thread too long.
        # The buffer was not filled in time — the user hears a glitch.
        print("Output underflow — consider increasing BLOCK_SIZE", flush=True)

    # Write audio data to the output buffer.
    # outdata shape: (frames, channels), dtype: float32, range: [-1.0, 1.0]
    outdata[:] = generate_audio(frames)

stream = sd.OutputStream(
    samplerate=SAMPLE_RATE,
    blocksize=BLOCK_SIZE,
    channels=1,
    dtype='float32',
    callback=audio_callback,
)
stream.start()
# ... Qt event loop runs here ...
stream.stop()
stream.close()

Audio data format

All audio data in sounddevice is a NumPy array with shape (frames, channels), dtype float32, and values in the range [-1.0, 1.0]. This is the universal format across the entire Python multimedia stack — the same array flows from sounddevice through NumPy DSP through SciPy filters and back out through sounddevice without any format conversion:

# Mono audio block: shape (512,) or (512, 1)
# Stereo audio block: shape (512, 2)
# Left channel: data[:, 0]
# Right channel: data[:, 1]

# NEVER pass an integer array to sounddevice — always float32
data = np.zeros((BLOCK_SIZE, 2), dtype=np.float32)  # correct
data = np.zeros((BLOCK_SIZE, 2), dtype=np.int16)     # WRONG — will produce noise

Thread safety

The audio callback runs in PortAudio's thread, not Qt's main thread. You must never call any Qt function from the callback. To send data from the audio thread to the UI, use a queue.Queue (which is thread-safe) and drain it in the main thread using a QTimer:

import queue
from PySide6.QtCore import QTimer

audio_queue: queue.Queue = queue.Queue(maxsize=50)

def audio_callback(indata, frames, time_info, status):
    # Put audio data in the queue — thread-safe, non-blocking with put_nowait
    try:
        audio_queue.put_nowait(indata.copy())  # always copy — indata is overwritten
    except queue.Full:
        pass  # UI is not keeping up — drop the block

# In the Qt main thread, a QTimer drains the queue at 30 fps
def on_timer():
    while not audio_queue.empty():
        block = audio_queue.get_nowait()
        waveform_canvas.set_data(block)  # safe — we are in the main thread

timer = QTimer()
timer.setInterval(33)   # ~30 fps
timer.timeout.connect(on_timer)
timer.start()
The audio callback is sacred ground. PortAudio calls it from a high-priority OS thread with tight timing constraints. Any delay — a memory allocation, a lock wait, a file read — can cause an underflow, which the user hears as a click or glitch. The callback should do exactly one thing: fill or drain the audio buffer. Everything else — UI updates, file I/O, heavy computation — belongs in the main thread, with a queue bridging the two.

5. Audio File I/O with soundfile

libsndfile is the professional C library for reading and writing audio files. It is used in Ardour, Audacity, ffmpeg, and countless broadcast and studio tools. soundfile is its Python interface. It supports WAV, FLAC, OGG Vorbis, AIFF, and CAF, and returns audio data as NumPy arrays in the same float32 format that sounddevice expects.

Reading audio files

import soundfile as sf
import numpy as np

# Read the entire file into memory

# data shape: (frames, channels), dtype: float32, range: [-1.0, 1.0]
# always_2d=True ensures mono files also return shape (frames, 1)

# Get file metadata without reading the audio
info = sf.info('audio.wav')

print(f"Channels:   {info.channels}")
print(f"Samplerate: {info.samplerate} Hz")
print(f"Format:     {info.format} / {info.subtype}")

Streaming large files

Loading a 2-hour film soundtrack into memory is not feasible. Use the SoundFile context manager to read in blocks:

BLOCK_FRAMES = 48000  # read 1 second at a time

with sf.SoundFile('long_audio.flac') as f:

Resampling

soundfile does not resample. If a file's sample rate does not match your audio device's sample rate (for example, a 44100 Hz file playing through a 48000 Hz device), you must resample it before playback. A pitch and speed error is the result if you do not. Use scipy.signal.resample_poly for high-quality rational resampling:

from scipy.signal import resample_poly
import math

def resample_audio(data: np.ndarray, orig_sr: int, target_sr: int) -> np.ndarray:
    """Resample audio to a new sample rate using polyphase filtering.

    resample_poly uses a polyphase filter bank — the same algorithm used
    in professional sample rate converters. It is far superior to naive
    linear interpolation.

    Args:
        data:      Audio array, shape (frames, channels), float32.
        orig_sr:   Source sample rate in Hz.
        target_sr: Target sample rate in Hz.

    Returns:
        Resampled audio array, same dtype and channel count.
    """
    if orig_sr == target_sr:
        return data
    gcd = math.gcd(orig_sr, target_sr)
    up   = target_sr // gcd   # upsample factor
    down = orig_sr   // gcd   # downsample factor
    return resample_poly(data, up, down, axis=0).astype(np.float32)
Always check the sample rate before playback. A 44100 Hz file played through a 48000 Hz device will sound flat and slow — it will play at 44100/48000 = 91.875% of its correct speed, a pitch drop of about a semitone. This is one of the most common bugs when integrating audio file playback into a desktop application. Always compare sf.info(path).samplerate to sd.query_devices(device)['default_samplerate'] and resample if they differ.

6. Digital Signal Processing with NumPy and SciPy

Audio is just numbers. Once you have loaded or captured audio data as a NumPy float32 array, every classical DSP operation — filtering, spectral analysis, synthesis, envelope shaping — is a mathematical operation on that array. This section covers the core DSP operations used in the demos.

Fourier analysis — FFT

The Discrete Fourier Transform (DFT) decomposes a time-domain signal into its frequency components. It answers the question: what frequencies are present in this audio, and at what amplitudes? This is the foundation of every spectrum analyser, equaliser, and codec.

For real-valued audio signals, always use numpy.fft.rfft (the real FFT). It is twice as efficient as the general fft because a real signal's spectrum is symmetric — you only need the positive frequencies:

import numpy as np

SAMPLE_RATE = 48000
NFFT = 2048            # FFT size — must be a power of two for efficiency

# Apply a Hann window before the FFT (explained below)
window = np.hanning(NFFT).astype(np.float32)
block  = audio_block[:NFFT] * window          # shape: (NFFT,)

# Compute the real FFT
spectrum = np.fft.rfft(block)                 # shape: (NFFT//2 + 1,) complex

# Convert complex spectrum to magnitude in dBFS
# +1e-9 epsilon prevents log10(0) = -inf
magnitude_db = 20.0 * np.log10(np.abs(spectrum) / NFFT + 1e-9)

# Compute the frequency axis (positive frequencies only)
freqs = np.fft.rfftfreq(NFFT, d=1.0 / SAMPLE_RATE)  # shape: (NFFT//2 + 1,)
# freqs[0] = 0 Hz (DC), freqs[-1] = SAMPLE_RATE / 2 (Nyquist)

Window functions and spectral leakage

The FFT assumes that the signal block repeats periodically. If the block contains a sine wave that does not complete an exact integer number of cycles within the block, there is a discontinuity at the boundary when the block is conceptually repeated. This discontinuity spreads the energy of that frequency across neighbouring bins — a phenomenon called spectral leakage.

Window functions solve this by tapering the block to zero at both ends, eliminating the discontinuity. The Hann window is the standard choice for audio spectrum analysis:

# Without windowing: spectral leakage spreads a 1 kHz sine across many bins
# With Hann window:  the energy is correctly concentrated in a few bins

from scipy.signal.windows import hann, hamming, blackman

hann_window     = hann(NFFT, sym=False).astype(np.float32)   # general purpose
hamming_window  = hamming(NFFT, sym=False).astype(np.float32) # slightly narrower main lobe
blackman_window = blackman(NFFT, sym=False).astype(np.float32) # very low sidelobes

IIR filtering with SciPy — the professional pattern

Infinite Impulse Response (IIR) filters are the workhorses of professional audio DSP. They achieve steep filter slopes with far fewer coefficients than FIR filters, making them efficient for real-time processing. The Butterworth filter provides a maximally flat passband with no ripple — the standard starting point for most audio applications.

The critical rule in professional code: always use second-order sections (SOS) form. Never use b, a transfer function form for filters above order 2. High-order b, a filters are numerically unstable at professional audio sample rates and will overflow or produce NaN with no warning:

from scipy.signal import butter, sosfilt, sosfilt_zi

SAMPLE_RATE = 48000

# CORRECT: design in SOS form
sos = butter(
    N=4,                    # filter order — higher = steeper rolloff
    Wn=1000,                # cutoff frequency in Hz
    btype='lowpass',        # lowpass, highpass, bandpass, bandstop
    fs=SAMPLE_RATE,         # sample rate — avoids manual normalisation
    output='sos',           # ALWAYS use 'sos' — not 'ba'
)
# sos shape: (N_sections, 6) — a cascade of second-order biquad sections

# WRONG: this will overflow for order > 2 at 48000 Hz
b, a = butter(4, 1000 / (SAMPLE_RATE / 2), btype='lowpass')   # DO NOT DO THIS

Offline filtering — applying a filter to a complete buffer

# Apply the filter to an entire audio buffer (offline DSP)
filtered = sosfilt(sos, audio_data, axis=0)
# axis=0 filters along the time axis — correct for (frames, channels) arrays

Real-time filtering — carrying filter state between blocks

When filtering block-by-block in a real-time callback, the filter must remember its internal state from one block to the next. Without this, each block is filtered as if it started from silence, producing a transient at every block boundary:

# Initialise filter state — zi has shape (N_sections, channels, 2)
# sosfilt_zi gives the correct initial conditions for a unit step response
zi = sosfilt_zi(sos)                   # shape: (N_sections, 2)
zi = zi[:, np.newaxis, :] * np.zeros((1, channels, 1))  # expand for multi-channel

# In the audio callback — filter the block and carry the state forward
filtered_block, zi = sosfilt(sos, input_block, axis=0, zi=zi)
# zi now holds the filter memory for the next callback call
# Without zi, each block starts fresh — you hear a click every BLOCK_SIZE samples

Waveform synthesis with phase accumulation

Generating a continuous tone in a block-based audio callback requires carrying the phase between blocks. If you reset phase to zero at the start of each block, the waveform restarts and you hear a click at every block boundary. Phase accumulation avoids this:

phase = 0.0   # carries between callback calls — store as instance variable

def generate_sine(frames: int, frequency: float, sample_rate: int) -> np.ndarray:
    """Generate one block of a sine wave using phase accumulation."""
    global phase
    # Time array: phases for each sample in this block
    t = phase + np.arange(frames, dtype=np.float32) * (2.0 * np.pi * frequency / sample_rate)
    # Advance the phase accumulator for the next block — wrap to [0, 2π]
    phase = float(t[-1]) % (2.0 * np.pi)
    return np.sin(t)
SOS form is not optional for professional code. A 4th-order Butterworth filter at a 20 Hz cutoff and 48000 Hz sample rate will silently overflow in b, a form — the transfer function coefficients span many orders of magnitude, exceeding float64 precision. The SOS cascade factorises the same filter into numerically stable 2nd-order sections. Every professional DSP library (MATLAB's Signal Processing Toolbox, LabVIEW, Simulink) outputs SOS by default. Always use output='sos'.

7. Audio Visualisation with QPainter

QPainter is Qt's 2D drawing API. You override paintEvent in a QWidget subclass and use QPainter to draw everything from scratch on every frame. This is the correct pattern for all audio visualisations — waveform displays, spectrum analysers, VU meters, and spectrograms.

The paintEvent cycle

from PySide6.QtWidgets import QWidget
from PySide6.QtGui import QPainter, QColor, QPen, QBrush, QPainterPath
from PySide6.QtCore import Qt

class WaveformCanvas(QWidget):
    """Custom QPainter widget for waveform display."""

    def __init__(self, parent=None):
        super().__init__(parent)
        self._data: np.ndarray | None = None

    def set_data(self, data: np.ndarray) -> None:
        """Receive new audio data and schedule a repaint.

        Never call paintEvent directly. Always call update() — Qt batches
        multiple update() calls in one event loop iteration into a single
        repaint, which avoids redundant drawing.
        """
        self._data = data
        self.update()   # schedule repaint — Qt calls paintEvent when ready

    def paintEvent(self, event) -> None:
        """Qt calls this to (re)draw the widget. Never call it directly."""
        painter = QPainter(self)
        painter.setRenderHint(QPainter.RenderHint.Antialiasing)

        w, h = self.width(), self.height()
        cy = h // 2   # centre Y — maps to audio value 0.0

        # Background
        painter.fillRect(0, 0, w, h, QColor("#0d0f14"))

        # Centre line
        painter.setPen(QPen(QColor("#252b38"), 1))
        painter.drawLine(0, cy, w, cy)

        if self._data is None:
            return

        # Draw waveform as a QPainterPath
        painter.setPen(QPen(QColor("#4f9cf9"), 1.5))
        path = QPainterPath()
        n = len(self._data)
        for i, sample in enumerate(self._data):
            px = int(i / n * w)
            py = int(cy - sample * cy * 0.9)   # scale to 90% of half-height
            if i == 0:
                path.moveTo(px, py)
            else:
                path.lineTo(px, py)
        painter.drawPath(path)
        painter.end()

Peak reduction for waveform display

A 3-minute stereo recording at 48000 Hz contains 8,640,000 samples per channel. Your display is perhaps 800 pixels wide. Drawing every sample would be 10,800× overdraw — impossible and unnecessary. The professional solution is peak reduction: for each pixel column, find the minimum and maximum sample value in the range of samples it covers, and draw a vertical line between them. This is visually identical to drawing every sample but 10,000× faster:

def peak_reduce(data: np.ndarray, width: int) -> tuple[np.ndarray, np.ndarray]:
    """Reduce audio data to per-pixel (min, max) pairs for waveform display.

    Args:
        data:  1D float32 array of audio samples.
        width: Target display width in pixels.

    Returns:
        Tuple of (peaks_min, peaks_max), each shape (width,).
    """
    n = len(data)
    samples_per_pixel = max(1, n // width)
    # Trim to an exact multiple of samples_per_pixel
    trimmed = data[:width * samples_per_pixel]
    reshaped = trimmed.reshape(width, samples_per_pixel)
    return reshaped.min(axis=1), reshaped.max(axis=1)

Logarithmic frequency axis for spectrum display

Human hearing is approximately logarithmic. The musical interval of an octave is always a doubling of frequency. On a linear frequency axis, all frequencies below 1 kHz — which contain most musical content — are compressed into 2% of the display width at a 48000 Hz sample rate. A logarithmic axis allocates equal visual space to every octave:

import numpy as np

F_MIN = 20.0      # lowest audible frequency, Hz
F_MAX = 20000.0   # highest audible frequency, Hz

def freq_to_pixel(f: float, width: int) -> int:
    """Map a frequency in Hz to a pixel x-position on a log-frequency axis.

    Formula: px = width * log10(f / F_MIN) / log10(F_MAX / F_MIN)
    This maps [F_MIN, F_MAX] → [0, width] on a log scale.
    Musical octaves appear equally spaced.
    """
    if f <= 0:
        return 0
    return int(width * np.log10(f / F_MIN) / np.log10(F_MAX / F_MIN))

8. Video Processing with OpenCV

OpenCV (Open Source Computer Vision Library) is the undisputed standard for frame-level video processing in Python. It is used in broadcast QC pipelines, VFX preprocessing, ML training data preparation, scientific imaging, and surveillance systems. In this chapter it provides the video decoding and frame processing layer of the multimedia application.

Reading video files

import cv2

cap = cv2.VideoCapture('video.mp4')

    raise RuntimeError(f"Cannot open video file: video.mp4")

# frame: NumPy array, shape (height, width, 3), dtype uint8, colour order BGR

cap.release()   # always release when done

The BGR colour order — the most common OpenCV bug

OpenCV uses BGR (Blue-Green-Red) channel order everywhere, not RGB. This is a legacy from its early interface with Windows BITMAPINFOHEADER structures. Every frame you read from OpenCV is BGR. Qt expects RGB. If you display a BGR frame as RGB, red and blue channels are swapped — faces appear blue. Always convert:

# ALWAYS do this before passing a frame to Qt
frame_rgb = cv2.cvtColor(frame, cv2.COLOR_BGR2RGB)

# Displaying on a QLabel via QImage and QPixmap
from PySide6.QtGui import QImage, QPixmap
from PySide6.QtCore import Qt

h, w, ch = frame_rgb.shape
bytes_per_line = ch * w   # CRITICAL: always pass this — see note below
qimg = QImage(frame_rgb.data, w, h, bytes_per_line, QImage.Format.Format_RGB888)
pixmap = QPixmap.fromImage(qimg)
label.setPixmap(
    pixmap.scaled(label.size(), Qt.AspectRatioMode.KeepAspectRatio,
                  Qt.TransformationMode.SmoothTransformation)
)
Always pass bytes_per_line to QImage. The fourth argument to the QImage constructor is the number of bytes per row. If you omit it, Qt uses a default that may assume 4-byte row alignment. For a frame with width not divisible by 4, this misalignment causes the display to appear diagonally shifted — a very confusing visual artefact. Always compute bytes_per_line = channels * width and pass it explicitly.

Frame-level DSP operations

Every frame is a NumPy array of shape (height, width, channels), dtype uint8. All OpenCV DSP functions operate in-place on these arrays, making them directly composable with NumPy operations:

# Grayscale conversion — reduces 3-channel to 1-channel
gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)   # shape: (H, W)

# Gaussian blur — noise reduction and pre-processing
blurred = cv2.GaussianBlur(frame, (15, 15), sigmaX=0)
# kernel size must be odd; larger = stronger blur

# Canny edge detection — the standard first-pass edge detector
# Operates on grayscale; the two thresholds define the hysteresis window
edges = cv2.Canny(gray, threshold1=50, threshold2=150)

# Histogram equalisation — contrast enhancement for poor exposure
equalized = cv2.equalizeHist(gray)

# Frame differencing — motion detection
diff = cv2.absdiff(prev_frame_gray, gray)
_, motion_mask = cv2.threshold(diff, thresh=25, maxval=255, type=cv2.THRESH_BINARY)

9. Audio/Video Synchronisation

Synchronising audio and video is one of the hardest problems in multimedia software. It is hard because audio and video are produced and consumed by different hardware clocks that run at slightly different rates. Professional A/V sync is an active, ongoing process — not a one-time alignment at startup.

Why sync is hard

Consider what happens when you start playback: you start the audio stream and the video decode loop. The audio stream runs on PortAudio's high-priority thread, driven by the audio hardware's crystal oscillator — extremely accurate. The video frame timer runs on a QTimer in Qt's main thread, which fires when the OS event loop gets to it — subject to OS scheduling jitter, GC pauses, and other delays. After a few minutes, these two clocks will have drifted relative to each other, and the lip sync you had at the start is gone.

Audio as the master clock

The professional solution is to make audio the master clock. The audio hardware DAC runs on a crystal oscillator with parts-per-million accuracy. PortAudio exposes this clock through the time_info argument of the audio callback. The outputBufferDacTime field gives you the exact time — in PortAudio's high-accuracy clock — when the first sample of the current buffer will reach the DAC.

Video frames are then displayed when their presentation timestamp matches the audio clock — not on a fixed timer:

import queue, time

dac_time_queue: queue.Queue = queue.Queue(maxsize=4)

def audio_callback(outdata, frames, time_info, status):
    # ... fill outdata with audio ...

    # Push the DAC timestamp to the main thread
    # outputBufferDacTime: seconds since PortAudio epoch when first sample hits DAC
    try:
        dac_time_queue.put_nowait(time_info.outputBufferDacTime)
    except queue.Full:
        pass   # main thread is behind — drop this timestamp

# PortAudio epoch offset — computed once at stream start
stream_start_dac: float = 0.0
stream_start_wall: float = 0.0

def on_display_timer():
    """Called by QTimer at ~60 Hz in the Qt main thread."""
    try:
        dac_time = dac_time_queue.get_nowait()
    except queue.Empty:
        return

    # Convert DAC time to a playback position in seconds
    playback_seconds = dac_time - stream_start_dac

    # Compute the video frame index
    target_frame = int(playback_seconds * video_fps)

    # Seek OpenCV to that frame and decode it
    cap.set(cv2.CAP_PROP_POS_FRAMES, target_frame)
    ret, frame = cap.read()
    if ret:
        display_frame(frame)

Audio extraction from video containers

OpenCV decodes video frames but does not decode audio. The standard professional approach is to use ffmpeg to extract the audio track to a WAV file before playback. ffmpeg handles every container and codec in professional use — MP4, MKV, AVI, MOV, H.264, H.265, VP9, AV1:

import subprocess, tempfile, pathlib

def extract_audio(video_path: pathlib.Path, target_sr: int = 48000) -> pathlib.Path:
    """Extract the audio track of a video file to a temporary WAV file.

    Uses ffmpeg, which handles every container and codec. This is the
    correct approach for a production application — do not attempt to
    decode audio with OpenCV.

    Args:
        video_path: Path to the input video file.
        target_sr:  Output sample rate in Hz.

    Returns:
        Path to the temporary WAV file. Caller is responsible for deletion.
    """
    tmp = tempfile.NamedTemporaryFile(suffix='.wav', delete=False)
    tmp.close()

    cmd = [
        'ffmpeg', '-y',              # overwrite output without asking
        '-i', str(video_path),       # input file
        '-vn',                       # no video output
        '-acodec', 'pcm_s16le',      # uncompressed 16-bit PCM — always readable
        '-ar', str(target_sr),       # resample to target sample rate
        '-ac', '2',                  # stereo output
        str(tmp.name),
    ]
    result = subprocess.run(cmd, capture_output=True, text=True)
    if result.returncode != 0:
        raise RuntimeError(f"ffmpeg failed:\n{result.stderr}")

    return pathlib.Path(tmp.name)

Atomic seeking

When the user drags the playback scrubber, both the audio and video streams must be seeked atomically — if audio restarts before the video seek completes, the streams immediately diverge. The correct sequence:

def seek_to_frame(target_frame: int) -> None:
    """Seek both audio and video to target_frame atomically."""
    # 1. Pause the audio stream — stops the audio callback
    audio_stream.stop()

    # 2. Seek the audio buffer pointer (protected by a Lock)
    with audio_lock:
        audio_frame_pos = int(target_frame * audio_sr / video_fps)

    # 3. Seek the video capture
    cap.set(cv2.CAP_PROP_POS_FRAMES, target_frame)

    # 4. Decode and display the target frame immediately (user sees it right away)
    ret, frame = cap.read()
    if ret:
        display_frame(frame)

    # 5. Restart the audio stream — audio and video are now aligned
    audio_stream.start()

Audio is always the master clock. This is not a convention — it reflects hardware reality. The audio DAC runs on a crystal oscillator with parts-per-million accuracy. Your system's time.time() does not. If you use the system clock as the A/V reference, you will drift. This is why VLC, ffplay, mpv, and every professional media player use audio-driven video presentation — the video renderer waits for the audio clock, not the other way around.

10. Building a Complete Multimedia Application

The final demo combines all components from demos 1–4 into a single multi-panel application. Before building it, it is worth understanding the architectural principles that separate a professional application from a collection of scripts stitched together.

The three thread boundaries

Every multimedia application in this chapter has three thread contexts, and you must know which operations belong in which context:

ThreadOwnerWhat runs hereWhat must NOT run here
Main threadQt event loopAll widget creation, all QPainter drawing, all signal emissions, all file dialogsBlocking I/O, long computations, audio callback code
Audio threadPortAudioThe sounddevice callback — fill/drain audio buffers, apply real-time DSPAny Qt call, memory allocation, blocking I/O, anything that can block
Decode thread (optional)Python threading.ThreadReading and decoding video frames ahead of time into a ring bufferQt widget access, audio buffer access without a lock

The bridge between these threads is always a queue.Queue. The audio thread pushes data into a queue; a QTimer in the main thread drains it at 30–60 fps and updates the UI.

Model / View separation

The most important architectural principle in multimedia tooling: the model (the data and logic) must have no knowledge of the view (the UI). In practice this means your audio engine, DSP chain, and video decoder are plain Python classes with no PySide6 imports. They accept NumPy arrays and return NumPy arrays. The Qt widgets are the view — they receive data through signals and display it. This separation makes every component independently testable and reusable.

Resource management

A multimedia application holds OS-level resources: audio device locks, video file handles, and temporary files. These must be released in a defined order when the application closes. Always implement closeEvent:

def closeEvent(self, event) -> None:
    """Release all resources before the window closes.

    Qt calls this when the user closes the window or calls app.quit().
    Failure to release resources here can lock the audio device for
    other applications until the OS recycles the process.
    """
    # 1. Stop the audio stream first — it holds a PortAudio device lock
    if self._audio_stream is not None:
        self._audio_stream.stop()
        self._audio_stream.close()

    # 2. Stop the display timer
    self._display_timer.stop()

    # 3. Release the video capture
    if self._cap is not None:
        self._cap.release()

    # 4. Delete temporary files (e.g. extracted audio WAV)
    if self._tmp_audio_path is not None and self._tmp_audio_path.exists():
        self._tmp_audio_path.unlink()

    # 5. Save user preferences
    self._save_settings()

    event.accept()

Persisting user preferences with QSettings

Professional applications remember the user's window size, last opened file, and selected audio device between sessions. QSettings handles this automatically on all platforms (the Windows registry, macOS plist, Linux INI file):

from PySide6.QtCore import QSettings

# Save on close

# Restore on startup

Error handling in multimedia applications

A multimedia application that crashes on a missing codec, a busy audio device, or a corrupt file is not professional. Every resource acquisition must be guarded, and every failure must produce a clear message:

from PySide6.QtWidgets import QMessageBox
