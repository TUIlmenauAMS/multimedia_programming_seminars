1. Textures: Images on Geometry

A texture is a 2D image stored in GPU memory. To apply it to geometry, every vertex gets a UV coordinate — a 2D point in the range 0…1 that says "this vertex corresponds to this spot on the texture". During rasterization the GPU interpolates the UV across the triangle, and the fragment shader samples the texture at that interpolated position with the built-in texture() function.

How the GPU reads a texel when the UV lands between pixels, or when the geometry is far away, is controlled by filtering parameters. NEAREST picks the closest texel (sharp, blocky). LINEAR blends the four nearest ones (smooth). For distant or small geometry, mipmaps — pre-computed half-resolution copies of the texture — prevent shimmering aliasing by letting the GPU sample from the appropriate level.

WebGL 2 removes the power-of-two restriction. In WebGL 1, mipmaps and REPEAT wrapping only worked on textures whose width and height were powers of two (1, 2, 4, 8, 16, 32, …). WebGL 2 lifts this restriction entirely — any size works. The checker texture here is 16×16 (a power of two anyway), and the detail texture is 200×200 (not a power of two) to demonstrate that mipmaps and repeat wrapping both work fine on it.

UV coordinates outside 0…1. When uvScale is greater than 1, the vertex shader multiplies the UVs by that factor, sending them outside the 0…1 range. The wrap mode decides what happens: REPEAT tiles the texture, MIRRORED_REPEAT flips it on every tile, and CLAMP_TO_EDGE stretches the edge pixels.

3. How It Works

This demo is Demo 4 with colors replaced by UVs and a texture sampler. The new steps:

  1. UV attribute. Each of the 24 vertices gets a vec2 UV: (0,0) at the bottom-left of its face, (1,1) at the top-right. The vertex shader multiplies by u_uvScale before passing the UV to the fragment shader.
  2. Procedural textures. Both textures are drawn on a hidden <canvas> element using the 2D API. No image file is needed — the cube can be opened from file://.
  3. Texture upload. gl.texImage2D(gl.TEXTURE_2D, 0, gl.RGBA, gl.RGBA, gl.UNSIGNED_BYTE, canvas2d). UNPACK_FLIP_Y_WEBGL is set to true before the upload: the 2D canvas has its origin at the top-left, but WebGL expects the origin at the bottom-left, so without flipping the texture would be upside-down.
  4. Mipmaps. gl.generateMipmap(gl.TEXTURE_2D) builds the mip chain automatically after upload. The chain halves the resolution at each level: 200×200, 100×100, 50×50, …, 1×1.
  5. Texture parameters. gl.texParameteri sets filtering and wrap mode on the currently bound texture. Changing a select calls it immediately.
  6. Texture units. gl.activeTexture(gl.TEXTURE0) selects unit 0; gl.bindTexture binds the texture to that unit. The sampler uniform is set to 0 (the unit index, not the texture object) with gl.uniform1i. Multiple textures are supported by using more units.

Why not just send pixels? A texture is uploaded once (or rarely) to GPU memory. During rendering, the GPU samples it millions of times per second from its on-chip texture cache — far faster than reading main memory. The filtering and mipmap logic is also implemented in dedicated fixed-function hardware.
