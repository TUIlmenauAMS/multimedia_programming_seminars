Demo 4 — ICE & Stats Inspector

04_mm_ice_stats.html · Loopback · Google STUN · Live ICE table, candidate pair, getStats() dashboard

A loopback RTCPeerConnection on this single page — no camera, no second tab, no copy-pasting. Both Peer A (offerer) and Peer B (answerer) live in this JavaScript runtime. The only purpose is to watch ICE work: every candidate that is gathered appears in the table on the left the moment it arrives, the nominated pair (the actual network path) is shown once ICE connects, and a live getStats() dashboard ticks every second on the right.

No camera required. The connection carries no media tracks — only the ICE/DTLS handshake runs. This is intentional: Demo 3 taught you signaling and SDP by making you copy-paste everything manually. Demo 4 removes that ceremony so you can focus entirely on ICE and stats. Demo 5 puts it all together with a real signaling server.
Uses Google STUN (stun.l.google.com:19302). In Demo 1 the loopback used no STUN server — only host candidates appeared. Here STUN is added so you also see a srflx (server-reflexive) candidate: your public IP:port as seen by the STUN server. That is what makes NAT traversal possible for real calls.

// CONCEPT: Candidate priority formula
Priority = (type_pref × 2²⁴) + (local_pref × 2⁸) + (256 − component). Type preferences: host 126 > srflx 100 > relay 0. ICE tries pairs highest-priority first, so a direct LAN path always beats a STUN-discovered public address, which always beats a TURN relay.

// CONCEPT: Nominated pair
ICE checks every local↔remote candidate combination. The winner — the highest-priority pair that passes connectivity checks — is nominated. getStats() identifies it with nominated === true on a candidate-pair entry. All traffic then flows on that single path until ICE restarts.

// CONCEPT: getStats() is a Map
await pc.getStats() resolves to an RTCStatsReport — a Map where each value's schema depends on its type field. Iterate with report.forEach(stats => { switch(stats.type) { … } }). Rates (bitrate, packet loss) must be computed by differencing two consecutive cumulative samples — getStats() reports totals, not instantaneous values.
