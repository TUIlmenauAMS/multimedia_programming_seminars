1. Visualizing Audio with AnalyserNode

The AnalyserNode is a pass-through node that exposes real-time analysis of the audio signal without modifying it. It provides two complementary views:

  • Time domain — amplitude as a function of time, displayed as an oscilloscope. Data is retrieved with getFloatTimeDomainData(), returning values in the range [−1, +1].
  • Frequency domain — magnitude spectrum computed via a Fast Fourier Transform (FFT). Data is retrieved with getFloatFrequencyData(), returning values in dBFS (decibels relative to full scale, where 0 dBFS is the maximum digital level).

The signal chain used in this demo is:

Source (OscillatorNode or MediaStreamSource) → GainNode → AnalyserNode → AudioContext.destination

3. Key Concepts

FFT size and resolution trade-off: The frequency resolution is fs / N Hz per bin, where fs = the sample rate (typically 44 100 or 48 000 Hz) and N is the FFT size. At N = 2048 this gives ≈ 21.5 Hz/bin; at N = 32768 it drops to ≈ 1.35 Hz/bin. A larger FFT also captures a longer time window — the two are inseparable (time–frequency uncertainty principle).

dBFS: getFloatFrequencyData() returns values in decibels relative to full scale. 0 dBFS represents the maximum representable digital level. Typical noise floors are around −90 to −96 dBFS for a 16-bit system.

Logarithmic frequency axis: Human pitch perception is approximately logarithmic — each octave doubles the frequency. A log-frequency axis maps each octave to equal horizontal space, which matches auditory experience. A linear axis compresses low frequencies and expands high ones.

Spectrum smoothing: A single FFT frame is noisy: even for a steady signal, each frame comes out slightly different, so the raw spectrum flickers. The AnalyserNode can average the spectrum over time through its smoothingTimeConstant (0 to 1). For every bin it computes Snew = τ · Sold + (1 − τ) · |X|, where |X| is the magnitude from the newest FFT frame and τ is the smoothing value (the averaging is done on linear magnitudes, then converted to dB). At τ = 0 you see every frame as it is: the fastest response, but a jittery trace. As τ approaches 1 the old value dominates: the curve is calm and easy to read, but peaks rise and fall slowly. The update runs once per drawn frame, so at 60 frames per second τ = 0.8 needs roughly 5 frames (≈ 80 ms) to follow a change and τ = 0.95 roughly 20 frames (≈ 330 ms). Smoothing does not change the frequency resolution (that is set by the FFT size) and does not affect the oscilloscope. Use low values to watch transients, such as a changing frequency or a plucked string, and high values to read a steady tone or the noise floor.

Oscilloscope time window: The scope reads its own analyser with the maximum buffer (32768 samples, about 743 ms at 44.1 kHz), so the window you choose is independent of the FFT size. Short windows show individual periods; long windows show envelopes and slow modulations.

Oscilloscope trigger: The display uses a rising-edge zero-crossing trigger to stabilize the waveform. Without it, the buffer start point shifts each frame and the waveform appears to scroll or jitter. A small hysteresis ignores noise near zero, and Free-run mode skips the trigger and simply shows the newest samples.
